# 数字教材资源脚本审核 Skill

一个用于审核数字教材资源脚本、课程旁白、课件文案和实验脚本的 Codex Skill。

它会通读脚本并检查知识准确性、前后逻辑、表述严谨性和术语规范性。对于知识性问题，Skill 会额外提取原文中的具体事实命题，形成可供后续查证的事实核验清单。

## 主要功能

- 检查概念混淆、数据错误、人物与年代错误、事实偏差等知识性问题。
- 识别前后不一致、自相矛盾、论据不足、因果倒置和实验变量控制失败。
- 发现绝对化、条件缺失、范围扩大、指代不清等不严谨表述。
- 检查学科术语、量名、单位、变量名称和专业表达是否规范。
- 区分脚本最终结论与角色的错误猜想、反例或待纠正观点。
- 结合年级和教学目标判断低龄比喻与教学简化是否合理。
- 材料缺页或不可读时明确审核范围，不冒充全文审核。
- 引用并定位存在问题的原文，不只给出笼统结论。
- 将复合事实拆成可独立验证的具体命题。
- 区分“待核实”和有权威来源支持的“已核实错误”。
- 给出尽量保留原意的修改建议。

## 安装

将仓库克隆到 Codex 的个人技能目录。

### Windows PowerShell

```powershell
git clone https://github.com/laotang98/reviewing-digital-textbook-scripts.git "$env:USERPROFILE\.codex\skills\reviewing-digital-textbook-scripts"
```

### macOS / Linux

```bash
git clone https://github.com/laotang98/reviewing-digital-textbook-scripts.git ~/.codex/skills/reviewing-digital-textbook-scripts
```

安装后重新打开 Codex，或开始一个新会话，使 Skill 被重新发现。

## 使用方法

在 Codex 中显式调用：

```text
使用 $reviewing-digital-textbook-scripts 审核下面的数字教材资源脚本：

【在这里粘贴脚本】
```

也可以补充审核要求：

```text
使用 $reviewing-digital-textbook-scripts 审核这份初中科学实验脚本。
请重点检查实验变量、术语和可能误导学生的表述；知识性问题先整理为待核实事实，不要自行视为已核实。
```

如果需要同时完成外部事实核验，可以明确提出：

```text
使用 $reviewing-digital-textbook-scripts 审核这份脚本，并用权威来源核验其中的知识性问题，附上来源链接。
```

## 审核范围

| 类别 | 重点内容 |
|---|---|
| 知识性问题 | 学科概念、数据、人物、地点、日期、因果关系、事实及适用条件 |
| 逻辑矛盾 | 前后不一致、自相矛盾、论据不支持结论、变量控制失败、因果倒置 |
| 表述不严谨 | 绝对化、条件缺失、指代不清、范围扩大、容易引起误解的表达 |
| 术语使用不当 | 学科术语、量名、单位、变量名称和专业表达的误用或混用 |

## 输出结构

审核结果通常由五部分组成；执行外部核验时会追加证据来源表：

1. **审核范围声明**：说明材料版本、已审核部分、缺失内容、学段信息和必要假设。
2. **总体结论**：通过、修改后通过、退修或范围受限，并概括主要风险。
3. **问题清单**：列出原文、问题类别、严重程度、判断依据和修改建议。
4. **事实核验清单**：单独提取知识性问题中的具体原文事实命题。
5. **全文一致性复核**：检查标题与正文、前提与结论、术语与单位是否一致。

问题清单示例：

| 编号 | 位置与原文 | 类别 | 严重程度 | 问题说明 | 修改建议 |
|---|---|---|---|---|---|
| 1 | “地球公转一周是24小时” | 知识性问题 / 术语使用不当 | 高 | 混淆了地球自转和公转的周期概念 | 核实地球运动方式及周期后改写 |

事实核验清单示例：

| 事实编号 | 关联问题 | 原文事实陈述 | 核验对象 | 当前状态 |
|---|---|---|---|---|
| F1 | 1 | “地球公转一周是24小时” | 地球公转周期及对应时长 | 待核实 |

## 事实核验原则

- 事实核验清单保留原文中的具体命题，不用正确答案替换错误原文。
- 一句话包含多个有疑点的事实时，会拆分为多个事实编号。
- 未查阅外部权威资料时，即使问题看起来很明显，也标记为“待核实”。
- 核验状态包括“待核实”“已核实正确”“已核实错误”和“证据不足”。
- 只有列出直接支持命题的权威来源后，才使用“已核实正确”或“已核实错误”。
- 来源互相冲突或证据不足时，保留冲突并标记为“证据不足”，不自行选择答案。
- 不把同一句中无争议的背景信息单独列为错误事实。

## 严重程度

| 等级 | 判定标准 |
|---|---|
| 高 | 核心概念、主要结论、实验设计或安全相关内容存在实质风险 |
| 中 | 局部知识、逻辑或适用条件可能造成误解，需要修改 |
| 低 | 局部术语或表达需要规范，但基本不影响核心理解 |

存在高风险问题时通常判为“退修”；仅有中低风险问题时判为“修改后通过”；材料不完整时使用“范围受限”，不对全文作出通过判断。

## 项目结构

```text
reviewing-digital-textbook-scripts/
├── SKILL.md
├── README.md
├── agents/
│   └── openai.yaml
└── tests/
    └── behavior-cases.md
```

- `SKILL.md`：审核规则、工作方法和输出约定。
- `agents/openai.yaml`：Codex 中显示的技能名称、简介和默认提示词。
- `tests/behavior-cases.md`：用于检验边界场景和防止行为回退的测试案例。

## 适用边界

本 Skill 的重点是知识准确性和表达严谨性。篇章风格、教学活动设计、画面表现和受众难度，只有在影响知识理解或准确性时才会作为问题提出。

“待核实”表示该命题需要通过可靠资料确认，不等于已经证明原文错误。

角色台词中的错误观点如果被后文及时、清晰并正确地纠正，不会被直接视为教材最终知识错误；审核重点转为纠正是否充分、是否仍会误导学习者。
